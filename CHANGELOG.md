# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- An RPM package (Fedora, RHEL, openSUSE) and an Arch package, both built and
  attached to every tagged release alongside the existing `.deb`. All three are
  architecture-independent and carry the same files: the `/usr` tree is built
  once by `packaging/lib-systree.sh`, so a path can no longer be fixed in one
  format and silently missed in the other two.
- A portable `tar.gz` with the same contents as the AppImage, for machines where
  an AppImage cannot be mounted. It shares its whole payload — bundled Python,
  Qt, OpenCV — with the AppImage through `packaging/lib-payload.sh`.
- `aarch64` builds of the AppImage and the tarball, from an ARM64 runner. They
  cannot be cross-built, because both are assembled with the interpreter they
  ship, so each architecture needs a runner of its own.

### Changed

- `aicampro-setup` installs the CPU build of PyTorch, with a warning, on
  anything that is not x86_64. ROCm publishes no ARM64 wheels, so the previous
  behaviour on the new `aarch64` builds would have been an unexplained pip
  failure at the end of a long download.

### Fixed

- The AppImage's `--shell` debug flag ran before `PYTHONPATH` was extended with
  the user runtime, so the interpreter it opened could not see PyTorch. Normal
  launches were unaffected.

## [0.1.1] - 2026-08-20

### Added

- A Debian package and an AppImage, built by the release workflow and attached
  to every tagged release. Neither bundles PyTorch: the ROCm build is roughly
  14 GB installed and has to match the amdgpu driver, so `aicampro-setup`
  fetches it once into the user's own directory.
- Desktop entry, an icon at eight sizes, and man pages for `aicampro` and
  `aicampro-setup`.

### Changed

- The model directory now resolves to `$XDG_DATA_HOME/aicampro/models` when the
  application is installed rather than run from a checkout, and honours
  `AICAMPRO_MODEL_DIR`. Installed builds could not write to the old location.

### Fixed

- The installed launcher loaded the wrong copy of the application when started
  from a directory containing `./aicampro/`, because both `python -m` and
  `python -c` put the working directory first on `sys.path`.
- Terminal detection in the launchers checked stdout, so a piped invocation was
  mistaken for a desktop launch and tried to open a terminal window.

## [0.1.0] - 2026-08-20

First public release. Everything below is new.

### Added

- Background handling: bokeh blur, image replacement, solid colour, virtual
  green screen and a transparent mode that exports alpha with snapshots.
- Colour grading — exposure, contrast, saturation, temperature, tint, gamma —
  plus 3D `.cube` LUT support and six LUTs generated by `scripts/make_assets.py`.
- Retouching: edge-preserving skin smoothing, sharpening and vignette.
- Auto-framing that follows the AI matte, or a detected face when matting is off.
- Virtual camera output through v4l2loopback, recording through ffmpeg with
  VAAPI hardware encoding on the AMD card, and stills.
- Camera hardware controls (exposure, gain, white balance and so on) read
  straight from V4L2, with a way back to the camera's defaults.
- Configurable output resolution, so you can capture at 1080p and output 720p
  and let auto-framing crop real pixels instead of upscaling.
- Presets that save and restore the whole look.

### Fixed

- Auto-framing stretched the image by 1.78x: the crop was computed by
  multiplying the aspect ratio into two quantities that were each normalised
  against a different axis, giving the crop an aspect of `aspect²`.
- Background image replacement did nothing at all —
  `BackgroundCompositor.set_image()` was never called anywhere, so the
  compositor silently fell back to a solid colour.
- Capture ran at half the frame rate (30 to 16 fps at 720p) because
  `CAP_PROP_BUFFERSIZE` was set to 1.
- Retouching used the pre-crop alpha, so its mask was misaligned once
  auto-framing was on.
- Resolution and encoder dropdowns always selected the first entry:
  `QComboBox.findData` compares non-trivial Python values by identity.
- Every label and slider rendered with a dark box behind it and square handles,
  because the Qt stylesheet set `background` on the blanket `QWidget` rule.
- Toggles had no knob and combo boxes had no arrow — neither can be drawn with
  a Qt stylesheet alone.
- `scripts/setup_v4l2loopback.sh` reported success while creating nothing:
  `modprobe` ignores parameters for an already-loaded module, and the config
  file it wrote was overridden by another one later in alphabetical order.
- Scrolling the control panel could change a slider or combo box under the
  cursor.
- Recordings taken in the same second overwrote each other.
